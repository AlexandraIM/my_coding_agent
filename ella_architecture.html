Ella: Архітектура та Можливості

Повноцінний автономний AI-асистент на базі Elixir/BEAM, створений для безпечної та результативної роботи безпосередньо з кодовою базою.

🔄 1. Як працює агент: Основний життєвий цикл

Ella реалізує автономний цикл взаємодії (Agentic Loop) на базі OTP GenServer. На відміну від звичайних чат-ботів, агент самостійно розбиває задачу на кроки, аналізує файлову систему, застосовує зміни та валідує результат.

flowchart TD User(["Користувач: Запит / План"]) --> Agent["Ella.Agent (GenServer)"] subgraph ContextMgmt ["Керування пам'яттю"] Agent --> CheckBudget{"Перевірка ліміту токенів?"} CheckBudget -- "Бюджет перевищено" --> ContextCompact["Ella.Context: Стиснення історії"] CheckBudget -- "В межах норми" --> LLMClient["Ella.LlmClient"] ContextCompact --> LLMClient end subgraph LLMExecution ["Виклик моделі"] LLMClient --> Stream["Ella.Stream: SSE Стрімінг & Повтори"] Stream --> Decision{"Що повернула модель?"} end Decision -- "Текстова відповідь" --> UserOutput["Owl.IO: Вивід користувачу"] subgraph ToolExecution ["Виконання інструментів"] Decision -- "Tool Call" --> SafetyCheck{"Перевірка режиму та Sandbox"} SafetyCheck -- "Plan Mode блокує запис" --> ToolError["Повернення помилки моделі"] SafetyCheck -- "Build Mode дозволяє" --> WriteGuard{"Захищений файл?"} WriteGuard -- "Так, потребує схвалення" --> ApprovePrompt["Ella.Approve: Запит у користувача"] ApprovePrompt -- "Дозволено / Ні" --> Snapshot["Ella.Snapshot: Резервна копія"] WriteGuard -- "Звичайний файл" --> Snapshot Snapshot --> ExecTool["Виконання: WriteFile / ApplyPatch / Exec"] ExecTool --> NextTurn["Результат інструменту в історію"] end NextTurn --> Agent UserOutput --> WaitUserInput(["Очікування наступного вводу"])
🛡️
Plan vs Build Режими
Plan Тільки читання (read_file, grep, glob, list_dir). Без ризику для проєкту.
Build Повний доступ (write_file, apply_patch, system_exec).
🧠
Динамічний контекст
Ella.Context автоматично стискає старі кроки у короткі підсумки. Сесія ніколи не обривається через переповнення ліміту токенів LLM.
⏪
Миттєвий відкат (/rewind)
Ella.Snapshot створює точкову копію кожного зміненого файлу. Команда /rewind повертає стан назад без впливу на git tree.

🛡️ 2. Багаторівнева система захисту (Safety First)

Головна проблема AI-асистентів — небезпека пошкодити код або запустити деструктивну команду в терміналі. В Ella реалізовано 4 лінії оборони:

flowchart LR Action["Дія Агента"] --> L1["Рівень 1: Sandbox"] L1 -->|"Заборона '..' та симлінків поза root"| L2["Рівень 2: Режими доступу"] L2 -->|"Plan Mode забороняє будь-який запис"| L3["Рівень 3: WriteGuard"] L3 -->|"Захист mix.exs, lockfiles, CI"| L4["Рівень 4: Deny-List Shell"] L4 -->|"Блокування rm, sudo, git reset"| SafeFS[("Безпечна файлова система")]
🔒 Ella.Sandbox
Ізолює всі операції в межах поточної робочої директорії. Жоден інструмент не може звернутися до /etc/passwd, ~/.ssh або вийти за межі репозиторію через символічні посилання.
🚫 Чорний список команд (SystemExec)
Агент принципово блокує запуск незворотних операцій: rm, sudo, dd, git push, git reset --hard, вимагаючи ручного виконання користувачем.

🔌 3. Розширюваність: MCP та Skills

🧩
Model Context Protocol (MCP)
Підтримка офіційного відкритого протоколу від Anthropic. Дозволяє підключати сторонні інструменти (інспекція бази даних, взаємодія з GitHub API тощо) прямо на льоту командою /mcp <cmd> без правки коду агента.
📚
Skills з прогресивним розкриттям
Кастомні Markdown-інструкції (наприклад, як запускати тести або правила стилю проєкту). Завдяки progressive disclosure, тіло інструкції підвантажується в контекст лише тоді, коли воно дійсно потрібне, заощаджуючи до 80% контексту.
